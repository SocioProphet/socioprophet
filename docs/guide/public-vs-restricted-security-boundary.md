# Public vs Restricted Security Boundary

SocioProphet intentionally separates what is public from what is restricted.

This is not inconsistency. It is part of the safety model.

## 1. What we publish publicly

We publish:

- product architecture
- governance model
- operator roles
- safety boundaries
- evidence and provenance model
- public-safe defensive posture
- institutional deployment logic
- reversibility and review principles
- deterministic and bounded AI claims at the architectural level

## 2. What we keep restricted

We restrict:

- sensitive operator kits
- high-fidelity adversary simulation internals
- tactical playbooks
- exploit or persistence workflows
- exact detection thresholds
- evasion-sensitive logic
- privileged deployment secrets
- other material that would materially raise misuse value

## 3. Why we do this

A serious system must not confuse transparency with irresponsibility.

We owe the public:

- clarity
- honesty
- auditability
- governance legibility

We do not owe the public:

- dangerous tactical detail
- misuse-enabling tool internals
- restricted runbooks or sensitive operator mechanics

## 4. Public-safe promise

We are willing to state plainly:

- what the platform does
- how it is governed
- what evidence it produces
- what we refuse to publish
- why those restrictions exist
